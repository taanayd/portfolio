How it works

Three core capabilities

01
Claude Sonnet 4.6 + ChromaDB RAG — every TC derives from actual IEEE standard text, not heuristics. LRM sections pinned verbatim into every generation prompt. Covers IEEE 1076-2008, 1076-2019, and 1800-2017.
02
4 simulators run in parallel — XSim 2026.1, VCS X-2025.06-SP2, Questa 2025.2, Riviera-PRO 2024.10. Identical TC suite, instant cross-simulator divergence diff via WebSocket live streaming.
03
5-round auto-fix loop — when a TC fails syntax check, Claude receives the compiler error and rewrites it automatically — up to 5 rounds. Bugs that take 20 min to debug resolve in seconds.

CR Batch
Verification Portal

Web GUI that fetches Verifier Assigned CRs from Jira, uses AI to read Steps-to-Reproduce, auto-generates produced_run.sh, and submits to the LSF cluster — 18× faster than running locally.

01
AI reads Steps-to-Reproduce — Genie AI (or Claude fallback) interprets the Jira CR description and auto-generates the simulation script.
02
LSF cluster submission — all CRs run in parallel on the farm. 32 GB RAM per CR. Job survives even if the browser closes.
03
Live-streamed results — WebSocket streams every simulation log line to the browser terminal in real time. HTML + CSV report generated on completion.

4 action modes

One portal, four workflows

Mode 01
List CRs
Queries Jira only — shows all Verifier Assigned CRs with title and status. No files touched. Safe for triage.
Mode 02
Setup (No-Run)
Creates directories, copies bugcase files, generates produced_run.sh via AI — but does not execute. Inspect before running.
Mode 03
Execute
Full run: setup + execute. Submits to LSF or runs locally. Generates HTML + CSV report. Shortcut: Ctrl+Enter.
Mode 04
Execute Live
Same as Execute but streams every log line live via WebSocket. Ideal for debugging individual CR failures in real time.
